# 地图画建造主流程优化方案（寻路 / 建造 / 放置校验 / 进度对账）

> 日期：2026-08-16 ｜ 状态：已批准实施 ｜ 范围：主流程 + 四大已知问题 + 放置后校验 + 进度对账
> 原则：以实际方块状态为唯一权威，DB 仅作进度记录；每次放置后校验；DB 与世界不一致以实际方块状态为准对账。
> 排除：服务器重启/掉线重连、断点续建异常场景、仓库缺货策略（保持一次一组 64）。

## 二、逐项方案

### P0-5 放置后校验与进度对账（核心，必含）
1. **坐标语义统一**：map_art_block_states 统一存世界坐标。create_task 落库转世界（origin+相对）；execute_map_art_start 重建 layers 转回相对供 matrix；_restore_progress 世界坐标过滤；get_task_blocks/placed 返回世界坐标。
2. **放置校验双层化**：
   - 弱确认（即时）：_genericPlace 无异常 + 手持匹配 + 本地复核（forceLocalBlock 后）→ DB placed=True、verified=False；
   - 强确认：服务器 blockUpdate 回显（blocks.js 记录）→ verified=True；
   - 行尾复核：对 verified=False 的行内坐标重读 world 复核，期望/air→verified=True，明确非预期→重置；
   - 完成前对账：completed 判定前对全部 verified=False 复核，未确认的按世界重置 → 防止「0/16384 却 completed」。
3. **聚合进度补全**：map_art_tasks.placed_blocks/verified_blocks 在 flush/对账时同步（COUNT 走索引）。

### P0-1 寻路强化
- chunk 走廊预检：pathfinder.js 对起点→目标矩形走廊内 chunk 预加载（上限等待）；
- world.js 未加载块保守填充：canWalkOn/canWalkThrough 未加载返回 false（配合走廊预检避免踩空）；
- executor.js 增强：ASCEND/PARKOUR jump 提前量细化；卡住先尝试 strafe 侧移再判失败；
- 行内直走恢复（护栏）：踩上移动用 walk_toward，仅当目标格脚下实体才允许，否则回退 _move_to。

### P0-2 坠落防护
- 站立模式改为「边放边踩」：bot 恒站刚放方块顶（脚 y=origin_y+1），行首站平台顶/上一行方块顶；行末蛇形转行零移动（行末方块顶直接放下一行行首）；
- 站立格前提校验：每格放置前确认目标站立点脚下实体，非实体 → 跳过并记待补，不触发传送兜底；
- 落地稳定复查：verify_height 双条件（y 偏差 + 脚下实体）。

### P0-3 防放错
- _ensure_item_in_hand 返回 bool：失败（补货也失败）→ 跳过该色，不进入放置（杜绝手持错误物品放错）；
- 放置前手持匹配校验（Node 侧 place_block 已有 heldItem 存在性检查，Python 侧在选物品层拦截）。

### P0-4 兜底状态机
- _try_teleport_home 按失败原因分流：teleport_no_effect（位置获取失败/不在区域）/ teleport_wrong_place / fall_after_teleport（y 不符/脚下空）→ 分别走「换下一级传送」「落地稳定化→寻路走回」「重传」；
- 重试上限提高：每级 2~3 次、总上限 6~8 次；重试参数 config 化；
- _verify_at_build_area 返回失败原因标签。

### P1 修复基线
- P1-1 config.py 站立层注释与代码值统一（coordinator 语义：offset=bot 脚 y 相对 origin_y，默认 0）；
- P1-2 双寻路 max_offset 一致（行内一律 1）；
- P1-3 verify_height 双条件（y 偏差 ≤1.0 且脚下实体）；
- P1-4 _restore_progress 坐标语义（与 P0-5 联动）。

### P2 工程增强
- 兜底决策日志（原因标签/次数/耗时）；
- 放置审计日志（目标/手持/参考面/弱确认/强确认 五元组 + 行尾统计）；
- 对账报告（启动/行/完成对账统计）；
- 重试/阈值参数收敛到 config。

## 三、实施顺序
P1 基线 → P0-5 进度权威 → P0-3 防放错 → P0-2 防坠落 → P0-4 兜底 → P0-1 寻路 → P2 观测。

## 四、验证方式
每步走真实执行链路：py_compile + node --check + 单测（test_astar.js 扩展）+ 真机单步（放置 1 格/1 行）+ 对账日志核对 + 任务级回归（57fff73484aa 断点路径、补货一次一组回归）。遵守部署铁律：`systemctl restart`、`pkill -f 'bot[_]main.js'`。
