## 一、现有架构的问题（定位结论）

## 三、坐标铁律（本次重构的根约定）

1. **内存/矩阵/相对坐标一律 0-based**：`x_rel ∈ [0, size_x-1]`、`z_rel ∈ [0, size_z-1]`；矩阵 key = `(x_rel, z_rel)`。
2. **世界坐标 = origin + 相对**：`wx = origin_x + x_rel`、`wy = origin_y`、`wz = origin_z + z_rel`。
3. **DB 存世界坐标**（现状不变）；API `/tasks/{id}/blocks` 一律返回世界坐标（修 B7）。
4. **列号 0-based**：`column_x ∈ [0, size_x-1]`；日志展示统一用世界 X（避免「列 1 = 世界 origin+1」的误解）。
5. 任何 1-based 只允许出现在「给用户看的序号」里，且必须显式 `+1`。

## 七、验收清单

1. 列式建造首个格子落在 `(origin_x, origin_y, origin_z)`，最后一列 `origin_x + size_x - 1`（坐标修复）。
2. 两引擎共用同一 `place_cell` 语义，无第二份放置校验代码。
3. 列式运行中 `add_bot`/`remove_bot` 不中断已建列、不重复建。
4. 暂停 → `build_progress.status == "paused"`。
5. 每 bot 进度在前端非 0（字段对齐）。
6. 缺块补放闭环（对账→补→复对账）在无缺口时零额外 WS 往返。
7. `py_compile` 全过 + 单测全过 + `vue-tsc` 全过。
